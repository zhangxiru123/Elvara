## 1. 通用约定

- Base URL：`http://localhost:8080`
- 接口前缀：`/api/auth`
- 编码：UTF-8
- 请求类型：`application/json`
- 时间格式：`yyyy-MM-dd HH:mm:ss`
- 登录后认证：`Authorization: Bearer <accessToken>`

统一成功响应：

```json
{
  "code": 0,
  "message": "OK",
  "data": {},
  "requestId": "5f3c2d1a-9b8e-4a6f-8c7d-2e1f0a9b8c7d"
}
```

统一失败响应：

```json
{
  "code": 40001,
  "message": "用户名已存在",
  "data": null,
  "requestId": "5f3c2d1a-9b8e-4a6f-8c7d-2e1f0a9b8c7d"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | number | `0` 成功，非 `0` 为业务错误 |
| `message` | string | 提示信息 |
| `data` | object / null | 业务数据 |
| `requestId` | string | 请求追踪 ID |

枚举约定：

| 字段 | 值 | 含义 |
|---|---|---|
| `sex` | `0` / `1` | 女 / 男 |
| `joinType` | `0` / `1` | 自动同意 / 需同意 |
| `status` | `0` / `1` | 正常 / 禁用 |
| `deviceType` | `WEB` / `IOS` / `ANDROID` / `DESKTOP` | 登录设备类型 |

用户对象 `UserInfo` 不返回密码：

```json
{
  "id": 10001,
  "username": "elvara_001",
  "email": "user@example.com",
  "nickName": "Elvara",
  "sex": 0,
  "icon": "/assets/default-avatar.png",
  "joinType": 1,
  "personalSignature": "Hello, Elvara!",
  "status": 0,
  "areaCode": 110000,
  "areaName": "北京市",
  "createTime": "2026-11-02 20:30:00",
  "lastLoginTime": "2026-11-02 20:35:12",
  "lastOffTime": null
}
```

## 2. 用户注册

接口：`POST /api/auth/register`  
是否需要登录：否  
成功状态码：`201 Created`

请求参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 4-20 位，字母开头，仅字母、数字、下划线 |
| `password` | string | 是 | 8-32 位，至少包含字母和数字 |
| `confirmPassword` | string | 是 | 必须与 `password` 一致 |
| `email` | string | 否 | 合法邮箱，最长 254 位；填写后全局唯一 |
| `nickName` | string | 否 | 1-24 位；为空时使用用户名 |
| `sex` | integer | 否 | `0` 女，`1` 男 |
| `areaCode` | integer | 否 | 地区编号 |
| `areaName` | string | 否 | 地区名称 |

请求示例：

```json
{
  "username": "elvara_001",
  "password": "Passw0rd!",
  "confirmPassword": "Passw0rd!",
  "email": "user@example.com",
  "nickName": "Elvara",
  "sex": 0,
  "areaCode": 110000,
  "areaName": "北京市"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "accessToken": "at_7Sf2c9Kx1aQp8mNv4rTz6wYb3jHd5eLu",
    "refreshToken": "rt_Mh4g2Dk8sLp0xVc6nQa9fJt3eWr7yUb1",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "refreshExpiresIn": 2592000,
    "user": {}
  },
  "requestId": "7d8f4e8b-6c7d-4d9e-a2b3-5e8f9a0b1c2d"
}
```

处理规则：

1. 用户名去除首尾空格，邮箱转小写。
2. 校验用户名、密码、邮箱格式和确认密码。
3. 检查用户名、邮箱唯一性。
4. 使用 BCrypt 加密密码，禁止明文存储或写日志。
5. 默认值：默认头像、`joinType=1`、`status=0`、当前时间。
6. 注册成功后直接签发 `accessToken` 与 `refreshToken`。
7. 写库与签发登录态应在同一业务事务边界内完成。

主要错误：

| HTTP | code | message |
|---|---|---|
| 400 | 40001 | 请求参数错误 |
| 400 | 40002 | 用户名格式不正确 |
| 400 | 40003 | 密码格式不正确 |
| 400 | 40004 | 两次输入的密码不一致 |
| 400 | 40005 | 邮箱格式不正确 |
| 409 | 40901 | 用户名已存在 |
| 409 | 40902 | 邮箱已被注册 |
| 429 | 42901 | 操作过于频繁，请稍后重试 |
| 500 | 50000 | 服务器内部错误 |

## 3. 用户登录

接口：`POST /api/auth/login`  
是否需要登录：否  
成功状态码：`200 OK`

请求参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `account` | string | 是 | 用户名或邮箱 |
| `password` | string | 是 | 原始密码 |
| `deviceId` | string | 是 | 客户端安装实例 ID |
| `deviceType` | string | 是 | `WEB` / `IOS` / `ANDROID` / `DESKTOP` |

请求示例：

```json
{
  "account": "elvara_001",
  "password": "Passw0rd!",
  "deviceId": "web-6b0f5a7c-55c4-4a6f-bc7d-3d09a8e5f012",
  "deviceType": "WEB"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "登录成功",
  "data": {
    "accessToken": "at_7Sf2c9Kx1aQp8mNv4rTz6wYb3jHd5eLu",
    "refreshToken": "rt_Mh4g2Dk8sLp0xVc6nQa9fJt3eWr7yUb1",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "refreshExpiresIn": 2592000,
    "user": {}
  },
  "requestId": "9a1d2c3b-4e5f-4a6b-8c7d-0e1f2a3b4c5d"
}
```

处理规则：

1. `account` 包含 `@` 时按邮箱查询，否则按用户名查询。
2. 使用 BCrypt 校验密码。
3. 账号不存在与密码错误统一返回“账号或密码错误”。
4. `status != 0` 时拒绝登录。
5. 更新 `last_login_time`，清理失败次数，签发新令牌。
6. 同账号允许不同设备同时在线。

登录保护：

- 同一账号 15 分钟内连续失败 5 次，锁定 15 分钟。
- 登录成功后清除失败计数。
- 建议同时按账号和 IP 限流。

主要错误：

| HTTP | code | message |
|---|---|---|
| 400 | 40001 | 请求参数错误 |
| 400 | 40006 | 设备信息不合法 |
| 401 | 40101 | 账号或密码错误 |
| 403 | 40301 | 账号已被禁用 |
| 429 | 42902 | 登录失败次数过多，请稍后重试 |
| 500 | 50000 | 服务器内部错误 |

## 4. 刷新登录态

接口：`POST /api/auth/refresh`  
是否需要登录：否

请求：

```json
{
  "refreshToken": "rt_Mh4g2Dk8sLp0xVc6nQa9fJt3eWr7yUb1",
  "deviceId": "web-6b0f5a7c-55c4-4a6f-bc7d-3d09a8e5f012"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "刷新成功",
  "data": {
    "accessToken": "at_4Kp8xTz2rWm6cNv9aQe1sLu3dHj7yFb5",
    "refreshToken": "rt_Nc3v7bQ1kLp5xZa8mRf2tYu6eWs9dHg4",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "refreshExpiresIn": 2592000
  },
  "requestId": "b7c8d9e0-1f2a-4b3c-8d4e-5f6a7b8c9d0e"
}
```

规则：

- 校验刷新令牌、过期时间和设备 ID。
- 刷新成功后旧刷新令牌立即失效。
- 旧访问令牌可主动删除或等待过期。
- 刷新失败返回 `401 / 40102`。

## 5. 退出登录

接口：`POST /api/auth/logout`  
是否需要登录：是

请求头：

```http
Authorization: Bearer <accessToken>
Content-Type: application/json
```

请求体：

```json
{
  "refreshToken": "rt_Mh4g2Dk8sLp0xVc6nQa9fJt3eWr7yUb1"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "退出成功",
  "data": null,
  "requestId": "c8d9e0f1-2a3b-4c5d-8e6f-7a8b9c0d1e2f"
}
```

规则：删除 Redis 中的访问令牌和刷新令牌，更新 `last_off_time`，接口应支持幂等调用。

## 6. 令牌与 Redis

| 项目 | 值 |
|---|---|
| 访问令牌有效期 | 7200 秒 |
| 刷新令牌有效期 | 2592000 秒 |
| 多设备 | 按 `userId + deviceId` 区分 |
| 访问令牌建议 | 32 字节随机值，Base64URL |
| 刷新令牌建议 | 32 字节随机值，Base64URL |

Redis Key 建议：

| Key | TTL |
|---|---|
| `elvara:auth:access:{accessToken}` | 7200 秒 |
| `elvara:auth:refresh:{refreshToken}` | 2592000 秒 |
| `elvara:auth:login:fail:{accountHash}` | 900 秒 |

刷新令牌必须轮换，建议使用 Redis Lua 脚本或分布式锁保证原子性。

## 7. 数据库约束

```sql
CREATE TABLE `user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT,
  `username` VARCHAR(20) NOT NULL,
  `password` VARCHAR(100) NOT NULL,
  `email` VARCHAR(254) DEFAULT NULL,
  `nick_name` VARCHAR(24) NOT NULL,
  `sex` TINYINT NOT NULL DEFAULT 0,
  `icon` VARCHAR(512) NOT NULL DEFAULT '',
  `join_type` TINYINT NOT NULL DEFAULT 1,
  `personal_signature` VARCHAR(120) NOT NULL DEFAULT '',
  `status` TINYINT NOT NULL DEFAULT 0,
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `area_name` VARCHAR(64) DEFAULT NULL,
  `area_code` INT DEFAULT NULL,
  `last_login_time` DATETIME DEFAULT NULL,
  `last_off_time` DATETIME DEFAULT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_username` (`username`),
  UNIQUE KEY `uk_email` (`email`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- 用户名和邮箱必须有唯一索引。
- 注册前做业务查重，数据库唯一索引作为最终兜底。
- 捕获唯一键冲突后转换为明确的业务错误。

## 8. 安全要求

1. 密码只能存 BCrypt 摘要。
2. 日志不得打印密码、完整令牌和验证码。
3. 账号不存在与密码错误使用统一提示。
4. 登录、注册、刷新接口必须限流。
5. 生产环境必须使用 HTTPS。
6. Web 端优先使用 `HttpOnly + Secure + SameSite` Cookie；使用 `localStorage` 时必须防 XSS。
7. 刷新令牌只能用于刷新接口。
8. 用户禁用、改密、退出时清理登录态。
9. WebSocket 握手必须校验 Token，不能信任客户端传的 `userId`。

## 9. 前端流程

注册：

1. 校验表单。
2. 调用 `POST /api/auth/register`。
3. 保存 Token 与用户信息。
4. 进入 IM 首页或资料完善页。

登录：

1. 调用 `POST /api/auth/login`。
2. 保存 Token 与用户信息。
3. 后续请求携带 `Authorization: Bearer <accessToken>`。
4. WebSocket 连接时同样携带访问令牌。

登录态失效：

1. 收到 `401 / 40102` 时调用刷新接口。
2. 刷新成功后重放原请求。
3. 刷新失败则清理状态并跳转登录页。
4. 并发 401 请求应合并为一次刷新。

## 11. 后端落地建议

```text
controller/AuthController
service/AuthService
service/impl/AuthServiceImpl
domain/dto/auth/*
domain/vo/auth/*
common/ApiResponse
common/ErrorCode
common/GlobalExceptionHandler
```

- Controller 只负责接收参数、校验和转换响应。
- Service 负责查重、密码校验、令牌签发和 Redis 操作。
- 使用 `@Validated` / Jakarta Validation。
- 使用 `@RestControllerAdvice` 统一异常。
- 密码使用 BCrypt。
- 登录态使用 Redis。
- Redis Key 统一加 `elvara:` 前缀。
